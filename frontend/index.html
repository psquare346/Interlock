Price tiers

the contract that grants them.

Suppliers send tier ladders in at least five incompatible shapes. All of them land as the same thing: contiguous, validated, effective-dated, and never valid past the contract.

Validated

An upward ladder is refused

Prices that rise with quantity are a parsing error in almost every real case, so the file is rejected rather than stored.

Effective dated

Send October pricing in September

A new ladder closes the old one instead of overwriting it. Historical requisitions stay auditable.

Shown to the buyer

Breaks surface before checkout

Once a cart returns to SAP the price does not re-resolve, so the next break is shown while there is still time to use it.

Procurement policy

A policy cannot outlive
the contract it rests on.

Write the rules, bind them to an agreement, activate. The effective window is clamped to the contract — so a policy quietly stops applying the day the agreement ends, rather than quietly continuing to.

REQUESTED
2026-01-01 → 2027-12-31
CONTRACT ACME-FY26
2026-04-01 → 2027-03-31
EFFECTIVE
2026-04-01 → 2027-03-31

effective_from = max(requested_from, contract.valid_from) · effective_to = min(requested_to, contract.valid_to)
Extending the contract does not extend the policy. That needs a new version, so somebody looks at it again.
